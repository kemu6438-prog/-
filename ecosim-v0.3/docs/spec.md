## 1. コンセプト

### 1.1 一句话コンセプト
**「あなたが地形と気候を作り、最初の数匹を放つ。あとは生物が自分で食べて、逃げて、学習して、世代を重ねて、あなたの世界に適応した“見たこともない動物”になっていく。」**

### 1.2 ピラー（設計判断の優先順位）

| # | ピラー | 意味 | トレードオフ時の判断 |
|---|---|---|---|
| P1 | **見て分かる進化** | 形・色・行動の変化が画面上で肉眼で追える | 見えない内部最適化より、見える変化を優先 |
| P2 | **因果が読める生態系** | 「なぜ増えた/絶滅したか」をグラフで説明できる | リアルさより説明可能性 |
| P3 | **プレイヤーが世界を作る** | 地形・気候・初期種・介入を自由に操作できる | 固定ストーリーより自由な実験場 |
| P4 | **放置しても回る** | 手を入れなくても生態系が自律的に動き続ける | 常時操作必須の設計にしない |
| P5 | **軽い** | 1台のノートPCのブラウザで 60fps | 表現の作り込みよりフレームレート |

### 1.3 非目標（やらないこと）
- 科学的に厳密な生態学シミュレーション（教科書的正しさより「もっともらしくて面白い」）
- リアルタイム対戦・共有ランキング
- 生物1匹1匹の物語（名前付け・感情移入システム）※観察用の追跡機能は持つ
- フォトリアルグラフィック

### 1.4 参考にした系譜
Karl Sims『Evolved Virtual Creatures』/ Spore（クリーチャーエディタ）/ Species: ALRE / Equilinox / Polyworld / Lenia / NEAT・CPPN

## 2. コアループ

```
        ┌───────────────────────────────────────────────┐
        │                                               │
   [作る] 地形・気候・水・初期生物をプレイヤーが配置      │
        │                                               │
        ▼                                               │
   [生きる] 個体が 感知 → 判断(NN) → 行動 → 代謝消費      │
        │      摂食 / 逃走 / 探索 / 学習（生涯学習）       │
        ▼                                               │
   [繁殖する] 十分なエネルギー → 交配 → 遺伝子組換＋変異   │
        │                                               │
        ▼                                               │
   [進化する] 環境に適した形質が個体群に広がる             │
        │                                               │
        ▼                                               │
   [観る] 系統樹・形質推移グラフ・個体追跡・絶滅ログ       │
        │                                               │
        └──→ プレイヤーが介入（気候変動・隕石・保護区）───┘
```

**1セッションの体験の流れ（想定 30〜90 分）**
1. 0分: 地形エディタで島を作る（5分）
2. 5分: 降雨・気温を設定、植物を撒く、草食獣10匹と肉食獣3匹を放す
3. 10分: 16倍速で観察。草食獣が増える → 草が減る → 餓死 → 振動
4. 25分: 脚の長い個体群と短い個体群に分岐。平原型と森型の違いが見える
5. 40分: プレイヤーが「寒波」を発生させる。毛皮遺伝子を持つ系統だけ生き残る
6. 60分: 系統樹を開き「どの分岐が生き残ったか」を確認、スクリーンショット

## 3. 技術スタック選定（理由つき）

| 領域 | 採用 | 理由 | 却下した案 |
|---|---|---|---|
| 言語 | TypeScript (strict) | 型安全が遺伝子スキーマ管理に必須、Web標準 | Rust+WASM（開発速度が落ちる。※Phase 5で要所だけWASM化は検討） |
| ビルド | Vite | 起動が速い、HMR | webpack |
| 3D | Three.js | 生态とエコシステムが最大、InstancedMesh/LODが揃っている | Babylon.js（重い）、raw WebGL（工数） |
| UI | React + zustand + Tailwind | パネル・グラフ類が作りやすい。シミュレーションとは完全分離 | 生DOM |
| グラフ | uPlot | 時系列を数十万点で軽く描ける（Chart.jsは重すぎる） | Chart.js / d3 |
| 状態管理 | シミュレーション: SoA `Float32Array` / UI: zustand | キャッシュ効率とGC回避 | クラスインスタンス配列（GC地獄になる） |
| 並列 | Web Worker 1〜N本 + `Transferable ArrayBuffer` | SharedArrayBuffer は COOP/COEP ヘッダが要り配布が面倒。transferで十分 | SharedArrayBuffer（`[TBD]` ローカル専用なら可） |
| 乱数 | 自前 xorshift128+（シード固定） | 再現性・リプレイ・デバッグに必須 | `Math.random`（再現不能） |
| 永続化 | IndexedDB（バイナリ） + `.ecosim.json` エクスポート | 遺伝子は float 配列なのでJSONだと巨大。バイナリ主体 | localStorage（容量不足） |
| 物理 | 自前の簡易剛体（地面高さに吸着 + 衝突は半径判定のみ） | 汎用物理エンジン（rapier等）は数千エージェントで破綻する | rapier-wasm |

### 3.1 なぜ「物理エンジンを使わない」のか
本ゲームで必要なのは「地面を歩く／水に浮く／体に当たる」の3つだけ。
- Y座標は地形ハイトフィールドから直接取得（`height(x,z)`）
- 斜面は「登坂可能な最大勾配」を超えたら速度減衰
- 個体間衝突は空間ハッシュ＋半径和判定で「押しのけ」のみ
これで数千体を 60Hz で回せる。汎用物理は入れない。

## 4. シミュレーション基盤

### 4.1 時間モデル

| 項目 | 値 |
|---|---|
| シミュレーション固定 dt | 1/60 秒（ゲーム内時間） |
| サブステップ | 最大 4（追いつかない時は間引く＝処理落ち） |
| 再生速度 | 停止 / 0.25× / 1× / 2× / 4× / 16× / 64× |
| 高倍速時の戦略 | 64× では描画を落とし、シミュレーションのみ回す（1フレームで最大16 tick） |
| ゲーム内1日 | 実時間 60秒（1×） |
| ゲーム内1年 | 4季 × 30日 = 120日 = 実時間 2分（1×） |

### 4.2 アーキテクチャ

```
┌─────────────────────── Main Thread ───────────────────────┐
│  React UI (zustand store)                                 │
│  Three.js Renderer  ← LOD / InstancedMesh / カリング        │
│  Input (Editor tools) → Command queue                     │
└───────────────▲──────────────────────┬────────────────────┘
                │ RenderSnapshot        │ CommandBuffer
                │ (transferable)        │ (transferable)
┌───────────────┴──────────────────────▼────────────────────┐
│                    Simulation Worker                       │
│  ┌────────────┐ ┌───────────┐ ┌──────────┐ ┌────────────┐ │
│  │ World(地形) │ │ PlantSys  │ │ AgentSys │ │ BrainSys   │ │
│  │ heightmap  │ │ grass/tree│ │ SoA      │ │ NN forward │ │
│  │ climate    │ │ soil      │ │ movement │ │ + 学習      │ │
│  └────────────┘ └───────────┘ └──────────┘ └────────────┘ │
│  ┌────────────┐ ┌───────────┐ ┌──────────┐ ┌────────────┐ │
│  │ SpatialHash│ │ Metabolism│ │ ReproSys │ │ Stats/Rec  │ │
│  └────────────┘ └───────────┘ └──────────┘ └────────────┘ │
│  決定論的 RNG (xorshift128+, seed 固定)                     │
└────────────────────────────────────────────────────────────┘
```

**設計原則**
- シミュレーションは DOM / Three.js に一切依存しない（Node.js でもヘッドレス実行できる＝自動バランス調整テストが可能）
- メインスレッド → Worker は「コマンド」（地形編集、スポーン、介入）
- Worker → メインスレッドは「描画スナップショット」（位置・回転・スケール・色・LODレベルの SoA）
- 1 tick の処理順序は固定（決定論性のため）:
  `気候更新 → 植物成長 → 感覚収集 → 脳 forward → 行動決定 → 移動 → 衝突 → 代謝 → 摂食/攻撃 → 繁殖 → 死亡 → 統計`

### 4.3 データ配置（SoA）
```ts
// 例: agents.ts
const MAX = 8192;   // docs/parameters.md の MAX_AGENTS
const posX   = new Float32Array(MAX);
const posZ   = new Float32Array(MAX);
const heading= new Float32Array(MAX);
const energy = new Float32Array(MAX);
const mass   = new Float32Array(MAX);
const alive  = new Uint8Array(MAX);
const genome = new Float32Array(MAX * GENOME_LEN); // 連続確保・行優先
```
- 死亡エージェントは「空きスロットリスト」で再利用（配列の詰替えをしない）
- `genome` は 1 個体 = `GENOME_LEN` floats の固定長。交叉・変異は単純な配列操作で済む

### 4.4 空間分割
- 均一グリッド（セル = 8m 四方）。地形セル（2m）とは別解像度
- 用途: 視覚対象探索 / 匂い源 / 衝突 / 捕食判定
- 毎 tick 再構築（数千体なら 1ms 未満）

## 5. 世界（環境）システム

### 5.1 座標系と地形

| 項目 | 値 |
|---|---|
| ワールドサイズ | 512m × 512m（`[TBD]` 256 / 512 / 1024 から選択可能に） |
| 地形セル | 2m × 2m → 256×256 = 65,536 セル |
| 高さ表現 | `Float32Array height[256*256]`（頂点ベース、セル中心は双一次補間） |
| 高さ範囲 | -20m 〜 +120m |
| 境界 | 海（ワールド外周は水没）または「壁」（設定で切替） |
| 法線 | 各頂点で事前計算し保持（斜面判定・描画ライティング共用） |

地形はプレイヤーが編集するため、**編集のたびに「派生データの再計算」が必要**：
- 法線、勾配
- 水流・窪地（水たまり）判定
- 気候マップ（気温・降雨の基盤）
→ 編集は「ブラシ単位でバッチ化」し、フレーム終わりに1回だけ再計算する（汚染矩形管理）。

### 5.2 水

| 項目 | 仕様 |
|---|---|
| 海抜 | `seaLevel`（デフォルト 0m、プレイヤー変更可） |
| 表現 | 水は「セルごとの水深 `waterDepth[]`」で持つ。描画は海面平面 + 水没セルの半透明 |
| 水循環（簡易） | `降雨 → 地表水 → 勾配に従い下流セルへ移動 → 低い窪地に溜まる → 蒸発 / 地下浸透` |
| 更新頻度 | 毎 tick ではなく 1 日 1 回（コスト対策） |
| 淡水 / 海水 | 塩分は持たない（v0.1）。`[TBD: 塩分 → 飲める水制限]` |
| 泳ぎ | 水深 > 脚長×0.5 で「遊泳モード」（速度減、エネルギー消費増）。水深 > 体高 で溺れゲージ減 |

### 5.3 気候

セルごとの静的マップ + 時間変動の合成で決める（フル流体シミュレーションはしない）。

```
気温(x,z,t) = 基礎気温
            - 標高 × 0.65℃/100m      (断熱減率)
            + 季節振幅 × sin(2π × 日/年 + 位相(緯度))
            + 日周期振幅 × sin(2π × 時刻/日)
            + 洋流/風向きによる補正(ノイズ)
            + 異常気象イベント補正

降雨(x,z,t) = 基礎降雨 × 地形性降雨係数(風上斜面で+、風下で-)
            × 季節係数 × 乱数揺らぎ
湿度(x,z,t) = f(降雨履歴, 水深, 植生密度, 気温)
```

**気候バイオーム**（ケッペンの簡易版・表示用）

| バイオーム | 条件 | 植物生産性 |
|---|---|---|
| 寒帯/雪 | 年均気温 < 0℃ | 0.15× |
| 乾燥/砂漠 | 降雨 < 200mm/年 | 0.10× |
| 草原 | 温暖・中降雨 | 1.0× |
| 森林 | 温暖・多雨 | 1.6× |
| 熱帯雨林 | 高温・多雨 | 2.2× |
| 水域 | 水深 > 0.5m | 0（水生植物は `[TBD]`） |

### 5.4 土壌と栄養

| 変数 | 単位 | 説明 |
|---|---|---|
| `soilN[]` | 窒素量 0〜1 | 植物成長の律速要因。分解で戻る |
| `soilP[]` | リン量 0〜1 | 同上（v0.1 では N と統合してもよい `[TBD]`） |
| `soilQuality` | 0〜1 | 岩石/砂/沃土。地形編集で変わる |

栄養は「死体・糞 → 分解者 → 土壌」で循環する（§5.6）。栄養が尽きると植物が生えず、草食獣が餓死し、生態系が崩壊する＝**プレイヤーが土壌管理をする動機**になる。

### 5.5 植物（生産者）

**2 種類から開始**（v0.1）

| 種 | 名前 | 特徴 |
|---|---|---|
| 草 | `grass` | セル単位のバイオマス。高速に増える。主食 |
| 木 | `tree` | セルごとの「密度 0〜1」。育つのに数年。遮蔽を作り気温/湿度に影響。実（果実）を落とす `[TBD Phase3]` |

**草の成長式（セル単位・1日1回更新）**
```
growth = baseRate × biomass × (1 - biomass/carryingCap)
       × f_light × f_temp × f_water × f_nutrient
biomass += growth - grazed - wither
```
| 係数 | 形 |
|---|---|
| `f_temp` | 最適温度20℃で1.0、0℃/45℃で0 の台形関数 |
| `f_water` | 土壌水分が最適帯 [0.3, 0.8] で 1.0、それ外で減衰 |
| `f_light` | 1 - 木密度×0.7（木陰では草が減る） |
| `f_nutrient` | `min(1, soilN / 0.3)` |

- `carryingCap` は気候で決まる（草原 100、砂漠 8）
- 食べられると `grazed` が増え、`biomass < 0.15×carryingCap` になると **過放牧ペナルティ**（回復速度が 0.2× になる、砂漠化リスク）
- **植物も進化するのか？** v0.1 では進化しない（環境の一部）。`[TBD Phase6: 植物にも「毒性」「棘」「成長速度」の遺伝子を持たせ、草食獣との軍拡競争を起こす]` ← これが本プロジェクトの最重要拡張候補

### 5.6 栄養循環と分解者

```
動物の死体 → corpse(cell, kg) → 分解速度で soilN に変換（数日）
動物の糞   → dung(cell, kg)   → 同上（速い）
枯草       → litter           → 同上
```
- 分解者は「不可視のフィールド処理」として実装（個別エージェントにしない＝コスト対策）
- `[TBD Phase4]` 腐肉食動物（スカベンジャー）を追加 → 死体が資源になり、食物網が三角になる

## 6. 動物（エージェント）システム

### 6.1 遺伝子スキーマ（Genome）

**設計方針**
- 1個体 = 固定長 `Float32Array`（長さ `GENOME_LEN ≈ 420`）
- 全遺伝子座は 0〜1 に正規化 → 実値への変換は `decode()` 関数が一括管理
- 相同染色体2本（父方/母方）を持ち、**優性/劣性**を表現 → 隠れた多様性が保持され、絶滅しにくくなる
  - `genome = [paternal(420), maternal(420)]` → 表現型は `allele[i] = mix(p[i], m[i], dominance[i])`
- 脳の重みも遺伝子配列の一部（§6.5）

#### 6.1.2 表現型デコード（例）

```ts
// 派生ステータス計算（毎世代1回＋成長時に再計算）
mass        = density * bodyLength * bodyWidth^2 * bodyHeight^2 * (0.6 + 0.4*muscleRatio)
maxSpeed    = 6.0 * legLength^0.5 * (1 - 0.3*fatRatio) * (1 - 0.4*armor) * (legCount==2 ? 1.15 : 1.0)
accel       = 12.0 * muscleRatio / mass^0.33
turnRate    = 3.0 / (bodyLength * mass^0.2)
bmrPerSec   = 0.9 * mass^0.75 * metabolismRate / 86400   // 基礎代謝
moveCost    = 0.35 * mass * speed^2                      // 毎秒・移動
coldStress  = max(0, preferredTemp - 10*(1-thermalTol) - ambientTemp)
heatStress  = max(0, ambientTemp - (preferredTemp + 10*(1-thermalTol)))
camouflage  = 1 - |bodyHue - terrainHue| * (patternType ? 0.6 : 1.0)
```

### 6.2 成長ステージ

| ステージ | 期間 | 特徴 |
|---|---|---|
| 幼体 (juvenile) | 0 〜 maturityAge | サイズ 0.4×、速度 0.7×、捕食されやすい、繁殖不可 |
| 成体 (adult) | maturityAge 〜 maxAge×0.7 | 繁殖可能、フル性能 |
| 老体 (senescent) | maxAge×0.7 〜 | 速度・繁殖力減衰、病死率上昇 |

成長中は質量・サイズが補間され、代謝・速度も連動して変化する（＝子供は食べられやすく、親は守る動機がある）。

### 6.3 代謝・エネルギー・ホメオスタシス

```
energy(t+1) = energy(t) + intake*efficiency - (bmr + moveCost + thermoCost + brainCost + growthCost)
```

| ゲージ | 範囲 | 0 のとき | 満タンのとき |
|---|---|---|---|
| energy | 0–100 × mass^0.9 | 死亡（餓死） | 繁殖に回せる |
| hydration | 0–100 | 死亡（脱水） | — |
| bodyTemp | 環境で決まる | 低温/高温ストレスで energy 減加速 | 最適帯でペナルティ無し |
| health | 0–100 | 死亡 | 被弾・病気・飢餓で減少、休息と食事で回復 |
| age | 0–maxAge | — | 老衰死 |

**体温モデル（簡易）**
```
bodyTemp += k * (ambientTemp + sunExposure - bodyTemp) / (mass^0.4 * (0.3 + fur))
thermoCost = |bodyTemp - preferredTemp| 超え分 × (1 - thermalTolerance) × C
```
→ 寒い地域で `fur` と `fat` と `mass`（ベルクマン則）が上がる、という**教科書的な進化が自然に起きる**ように設計する。

### 6.5 脳（Neural Network）

**アーキテクチャ: 固定トポロジー MLP（3層）＋ 生涯学習**

```
inputs(32) → hidden1(H=12) → hidden2(H=12) → outputs(14)
重み数 = 32*12 + 12*12 + 12*14 = 384 + 144 + 168 = 696
バイアスは入力層の bias(32番目) と hidden 側 12+12 で賄う（追加スロット無し）
```

#### 6.5.0 「脳の大きさ」を可変長にしない理由（重要）

可変長の NN（H が個体ごとに違う）にすると、SoA の連続メモリが崩れ、
ゲノム長が個体ごとに変わり、交叉も描画スナップショットも全部複雑化する。
そこで **トポロジーは全個体で H=12 固定** とし、`brainSize` 遺伝子は次の2つで効かせる:

| brainSize の作用 | 内容 |
|---|---|
| **有効ユニット数** | `activeH = 4 + round(brainSize * 8)`（4〜12）。`activeH` を超える隠れユニットは forward 時に 0 に潰す → 実効的な脳容量が進化する |
| **代謝コスト** | `brainCost = coef * activeH^1.2 * mass^0.25` → 大きい脳は餌を食う。知能が「タダで進化しない」ようにする |

これにより「脳が大きいほど賢いが餌がかかる」というトレードオフが成立し、
**知能が進化するかどうか自体が環境次第になる**（＝本ゲームの狙いそのもの）。

> 重みを全部遺伝子に持たせるとゲノムが肥大するが、696 floats なら許容範囲（§6.1 の 3.26 KB/個体）。
> 交叉は「層単位で親A/親Bを選択 → ブレンド率 0.5 で混合 → 変異」で行い、破壊的組換を避ける。

| 方式 | ゲノム長 | 進化のしやすさ | 実装難度 | 判定 |
|---|---|---|---|---|
| A. 直接符号化 MLP（H固定12） | 696 | 局所最適に陥りやすいが十分 | 低 | **採用（Phase 3）** |
| B. CPPN 間接符号化 | 〜60 | 滑らか・対称性が出やすい | 中 | Phase 3 で A/B 比較 |
| C. NEAT（構造も進化） | 可変 | 最強だが実装・デバッグ重 | 高 | 見送り（個人開発では過剰） |

### 6.6 生涯学習（個体適応）

**目的**: 「1匹の人生の中でも環境に合わせる」＝進化（世代）だけでは遅すぎる変化に対応させる。

| 方式 | 内容 | 採用 |
|---|---|---|
| 報酬学習（3-factor Hebb） | `ΔW = η · plasticity · pre · post · reward` | ◎ 主軸 |
| 報酬信号 | `R = +k1·摂食カロリー + k2·被ダメージ(-) + k3·体温ストレス(-) + k4·繁殖成功 + k5·子の生存` | ◎ |
| 行動価値テーブル（簡易Q） | 状態を離散化して「食料がある方角」等を覚える | △ オプション |
| 模倣学習 | 親・群れの個体の行動を複製する | `[TBD Phase4]` 文化の萌芽 |

- 学習は **出力層直前の重み** のみ更新（コストと安定性のため）
- `plasticity`（N02）と `brainSize`（N01）は遺伝するので、**「学習しやすい脳」自体が進化する**（Baldwin 効果）
- **学習結果の遺伝への書き戻し**（ラマルク的）: 既定 OFF。実験オプションとして「個体の生涯で変化した重みの λ 倍を子に継承」を ON 可能 → 進化速度が劇的に上がるが、環境変化に弱くなる。`[TBD: デフォルト値]`

### 6.7 行動実行と移動

```
desiredSpeed = forward * maxSpeed * f(energy, health, terrain, water)
heading     += turn * turnRate * dt
pos         += dir(heading) * desiredSpeed * dt
y            = terrainHeight(pos) + legLength*0.5 + bodyHeight*0.5
```
- 登坂制限: `slope > atan(legThickness系)` なら速度 × (1 - 超過分)
- 群れ: `sociability` が同種近傍からの引力/整列力をスケール（Boids の簡易版、学習出力 `herd` で上書き可能）
- ナビゲーション: 障害物（岩・木）は空間ハッシュで避け。**経路探索（A*）は使わない**（数千体で破綻）。代わりに「勾配と匂い梯度を登る」リアクティブ方式

### 6.8 摂食

| 対象 | 条件 | 得られるエネルギー |
|---|---|---|
| 草 | 足元セルの `grass > 0`、`eat`出力 ON、toothType が草食寄り | `min(胃空き, grass × biteSize × efficiency)` |
| 木の実/葉 | neckLength が閾値以上 | 同上 |
| 死体 | 半径内、腐敗前 | 高カロリーだが病気リスク |
| 生きた動物 | `bite`、射程内、相手の armor/health で減衰 | 与ダメージ分の一部 |

**diet（L01）が全ての効率を決める**
```
efficiency_plant = digestiveEff * (1 - diet)          // diet=1(完全肉食)だと草を消化できない
efficiency_meat  = digestiveEff * diet * (0.5 + 0.5*toothType)
```
→ diet が中間の**雑食**は両方を中途半端にしか使えない。このトレードオフが「草食／肉食の分岐」を自然に生む。

### 6.9 捕食と戦闘

```
damage = biteForce(mass, muscle, hornSize, clawSize) * dt * (1 - target.armor*0.7)
target.health -= damage
逃走判定: 相手が fleeBoost 中なら distance が開く → 攻撃側のスタミナが切れると中断
```
- 攻撃側・防御側とも `aggression` / `boldness` の遺伝子＋学習出力で意思決定
- **捕食成功は学習の強力な報酬**なので、賢い狩り方（待ち伏せ、群れでの追込み）が生涯学習で獲得されうる

### 6.10 繁殖

| 項目 | 仕様 |
|---|---|
| 条件 | 成体 ∧ energy > 60% ∧ health > 40% ∧ 発情中（季節依存）∧ 相手が半径 3m 内 ∧ 両者 `court` 出力 ON |
| 配偶者選択 | `mateSelectivity` が高いほど `matePreferenceHue` と相手の体色/形質を照合して選り好みする（**性的選択**） |
| 回数制限 | 1産後 `gestationCost` 相当のクールダウン |
| 産子数 | `litterSize`（1–8）。多いほど1匹あたりの初期エネルギーが少ない |
| 子のゲノム | 相同2本の交叉（組換点 2〜4 か所）＋突然変異 |
| 初期エネルギー | 親の energy を分配（親は消費） |
| 近親交配 | 血縁度 > 0.5 なら子の健康度にペナルティ（近交弱勢）→ 多様性維持 pressure |
| 単為生殖 | オプション（サンドボックスでON可） |

**突然変異パラメータ**

| 項目 | 既定値 |
|---|---|
| 遺伝子座ごとの変異確率 | 0.03 |
| 変異の大きさ | 正規分布 σ=0.08（0–1正規化空間） |
| 大規模変異（ジャンプ） | 0.5% の確率で σ=0.35 |
| 交叉率 | 0.9 |
| 重み遺伝子の変異率 | 0.02（形質より低め：脳が壊れやすいため） |
| **環境ストレス連動** | 個体群密度が低い/絶滅危惧時に変異率 ×2（SOS応答的な仕組みで絶滅を防ぐ） |

### 6.11 死亡

| 原因 | 判定 |
|---|---|
| 餓死 | energy ≤ 0 |
| 脱水 | hydration ≤ 0 |
| 捕食 | health ≤ 0 |
| 老衰 | age ≥ maxAge |
| 温度ストレス | 体温逸脱が一定時間継続 |
| 溺死 | 水深超過で health 減少 |
| 病気 | 疫病イベント時の抽選（diseaseResistance で減衰） |
| 転落 | 高低差 > 閾値 の落下ダメージ |

死体は地面に `corpse` として残り、分解されるか腐肉食動物に食べられる（数日で消失）。

### 6.12 種（Species）の定義

**「種」はプレイヤーが命名するものではなく、システムが推定する。**

```
個体の形質ベクトル X (30次元) を取り、
種クラスタ = 相互に「繁殖可能な最近傍グループ」
実装: 
  1) 各エージェントに speciesId を付与（親から継承）
  2) 形質距離 > threshold の変異が累積したら新 speciesId に分岐（分岐イベントをログ）
  3) 表示名は自動生成（"グラッサス・ロングクルス #12" のような ラテン語もどき）
```
- 系統樹はこの speciesId の分岐履歴から構築される
- 生殖隔離（別種間では交配できない）は v0.1 では「形質距離が大きいと求愛が成立しない」で近似

| 個体を選択して編集 | 生きている個体の遺伝子を直接書き換える（チートだが実験に有用） |
| 遺伝子固定 | 特定遺伝子座に変異が入らないようロック |
| 変異注入 | 選択個体にランダム変異を大量発生させる |
| 絶滅させる | 種を一掃 |
| 保護区 | 範囲内を捕食・介入から守る（リザーブ） |
| 壁 / フェンス | 通行不能ラインで生息域を分断 → **地理的隔離による種分化**を実験できる |

**D. イベント（災害）ツール**

| イベント | 効果 |
|---|---|
| 隕石 | 範囲内の生物即死、地形クレーター、数年の寒冷化（粉塵） |
| 寒波 / 熱波 | 期間限定で気温 ±15℃ |
| 干ばつ / 豪雨 | 降雨を 0 / 3倍に |
| 山火事 | 植生を焼き、土壌栄養を一時的に増やす |
| 疫病 | 個体群に感染拡大（density依存） |
| 洪水 | 海抜を一時的に上げる |
| 火山 | 新地形の生成＋栄養供給＋局所絶滅 |
| 外来種投入 | 別ワールドから種を移入 |

> これらは「進化の方向をプレイヤーが舵取りするハンドル」であり、**選択圧そのもの**である。

### 7.2 選択圧スライダー（本ゲーム独自の中核UI）

「進化を直接いじる」パネル。以下を 0〜1 で設定でき、内部的には報酬関数・死亡率・繁殖条件に効く。

### 8.2 「主観視点」の実装（重要）
選択個体の NN 入力ベクトルをそのまま可視化する（32本のバー＋検出対象へのハイライト線）。
→ **AIが何を感じて何をしようとしているか**が一目で分かる。これは本ゲームの最大の"知的好奇心フック"。

### 8.3 統計の保存
毎ゲーム内日で以下を記録（リングバッファ、既定 5,000 日分）:
`種別個体数, 出生, 死亡原因別, 平均形質(全遺伝子座), 草バイオマス総量, 気候, 多様性指標`
→ グラフとエクスポート（CSV/JSON）に使用。

### 9.3 UX原則

3. **いつでも止められる**: 一時停止で世界が完全に止まり、その状態で編集できる
4. **失敗を責めない**: 全滅しても「絶滅レポート（何が原因か）」を出して、リスタートを促す
5. **操作を1つ覚えたら1つ見える**: 各パネルに「この値を上げるとどうなるか」のツールチップ

### 11.2 Worker プロトコル

```ts
// Main → Sim
type Command =
  | { t:'tick'; count:number }                       // 高倍速用まとめtick
  | { t:'terrain'; brush:TerrainBrush }
  | { t:'climate'; patch:Partial<ClimateParams> }
  | { t:'spawn'; species:PresetId|GenomeDump; n:number; at:{x,z} }
  | { t:'editAgent'; id:number; patch:Partial<GenomeDump> }
  | { t:'event'; kind:EventKind; params:any }
  | { t:'selectPressure'; values:PressureVector }
  | { t:'setSpeed'; mul:number }
  | { t:'save' } | { t:'load'; blob:ArrayBuffer }
  | { t:'setSeed'; seed:number }

// Sim → Main (毎描画フレーム、あるいは n tick ごと)
interface Snapshot {
  time: number; day: number;
  agents: {                     // 全て transferable Float32Array
    ids: Int32Array;            // 生存エージェント
    x: Float32Array; y: Float32Array; z: Float32Array;
    yaw: Float32Array; pitch: Float32Array;
    scale: Float32Array;        // 体型スケール
    hue: Float32Array; sat: Float32Array; lum: Float32Array;
    stage: Uint8Array;          // 幼体/成体/老体
    species: Int32Array;
    gait: Float32Array;         // 脚アニメ位相
  };
  terrainDirty: { x0:number; z0:number; x1:number; z1:number } | null;
  heightPatch?: Float32Array;   // 編集時のみ
  vegPatch?: { cells:Int32Array; grass:Float32Array; tree:Float32Array } | null;
  stats: StatsFrame;            // グラフ用集計（間引き）
  log: LogEvent[];              // 分岐・絶滅・イベント
  selected?: AgentDetail;       // インスペクタ用（要求時のみ）
}
```
- 3,000体 × 12 float ≈ 144KB/フレーム → 毎フレーム transfer は厳しいので **30Hz に間引く**
- 選択個体の詳細（ゲノム全文、学習重み、生涯履歴）は**要求時のみ**送信

### 11.3 決定論性とリプレイ
- 全乱数は `Rng(seed)` から派生した**ストリーム分離**（地形用/変異用/気候用…）で管理
- コマンド列 + シードを保存すれば完全再現可能 → **「進化のリプレイ」**機能（Phase5）
- 浮動小数点の非決定性を避けるため、tick 内の反復順序はインデックス昇順に固定

### 11.4 セーブ形式

```
.ecosim (ZIP)
├─ manifest.json      # version, seed, worldSize, createdAt, サムネPNG
├─ world.bin          # heightmap, soil, water, climate params (Float32Array raw)
├─ plants.bin         # grass[], tree[] (Uint16 量子化)
├─ agents.bin         # 生存個体の genome + state
├─ species.json       # 系統樹、種メタ
├─ stats.bin          # 統計履歴（間引き済み）
└─ commands.jsonl     # (任意) リプレイ用コマンドログ
```
- 保存先: IndexedDB（自動セーブ 5分ごと + 手動スロット 10個）
- エクスポート: `.ecosim` ファイルのダウンロード／ドラッグ&ドロップでインポート
- `[TBD]` バージョン移行戦略（遺伝子スキーマ変更時の後方互換）→ スキーマは `SCHEMA_VERSION` を持ち、追加は末尾のみ・削除は禁止、というルールで運用

### 11.5 レンダリング戦略

| 要素 | 手法 |
|---|---|
| 地形 | 256×256 を 8×8 チャンクの PlaneGeometry に分割。編集チャンクのみ再構築。テクスチャスプラッティング（岩/土/草/砂/雪）を 1 パスで |
| 水面 | シンプルな平面 + 法線アニメ + 反射は fake（env map） |
| 草 | 高密度セルはテクスチャで表現、近景のみ InstancedMesh の cross-plane。バイオマスで色とスケール |
| 木 | InstancedMesh（幹＋葉の2種）。LOD でビルボード |
| 動物 | **部位ごとの InstancedMesh**（胴体=box/sphere, 頭, 脚×4, 尾, 装飾）。1体あたり最大 8 インスタンス |
| LOD | 近(<25m): フル部位 / 中(25–80m): 胴体+頭 / 遠(>80m): 1枚のビルボード / 極遠: 点 |
| 影 | 太陽のディレクショナルシャドウは 1024、近景チャンクのみ。動物の影は LOD 近のみ |
| ポストFX | Bloom（弱）、SSAO（オフ可）、色調整。トグルで無効化可能 |

**スケール手段**

3. 個体群が閾値超で「エージェントの抽象化」（個体をやめて個体群微分方程式に切替）※これは最終手段 `[TBD]`
4. Web Worker を複数に分割（地域分割）`[TBD Phase5]`

## 13. 数値バランス方針

### 13.1 狙う個体群動態
- 草食獣: 300 〜 2,000 体で振動（周期 2〜5 ゲーム年）
- 肉食獣: 30 〜 200 体（草食獣の 1/10 程度、生態ピラミッド準拠）
- 植物バイオマス: 総量の 20〜60% が常時残る（完全裸地化は失敗状態）
- 種の平均寿命: 20〜80 ゲーム年（絶滅と分岐が「ほどよい頻度」で起きる）

### 13.2 バランス調整の手法
**手作業でいじらない。ヘッドレス自動テストで作る。**
```
src/headless/runBatch.ts
  → 描画なしで 100 ゲーム年 × 32 パラメータセット を並列実行
  → 「草食獣が 30〜2000 の範囲に収まる日数の割合」をスコア化
  → 簡易 CMA-ES / グリッドサーチでパラメータを探索
  → docs/parameters.md に結果を書き戻す
```
これは TypeScript で sim を DOM 非依存にしたことで可能になる（＝**設計の最重要ポイント**）。

### 13.3 主要チューニングノブ

| ノブ | 既定 | 上げると |
|---|---|---|
| `grassBaseRate` | 0.035/日 | 草食獣が増える |
| `bmrCoef` | 0.9 | 代謝が厳しくなり個体数が減る |
| `moveCostCoef` | 0.35 | 移動のコスト増 → 待ち伏せ型が有利 |
| `reproEnergyThreshold` | 0.6 | 繁殖が難しくなる |
| `litterSizeMax` | 8 | r戦略が有利 |
| `mutationRate` | 0.03 | 進化が速く、不安定 |
| `brainCostCoef` | 0.02 | 脳がコストになり、知能が進化しにくい |
| `predationEfficiency` | 0.35 | 捕食が成功しやすくなる |

### Phase 1 — 生態系の心臓（2〜4週）
- [ ] 気候（気温・降雨・季節）フィールド
- [ ] 草のセルオートマトン（成長・被食・枯死・栄養）
- [ ] FSM（状態機械）の草食獣：`wander / graze / flee / rest / mate`
- [ ] 代謝・エネルギー・死亡・単純繁殖（遺伝子なし、形質はランダム固定）
- [ ] 個体数グラフパネル
- **受入基準**: 草食獣が増減を繰り返すロトカ・ヴォルテラ的な振動が 100 年安定して観測できる

### Phase 2 — 遺伝と形態進化（3〜5週）
- [ ] Genome スキーマ（相同2本）実装、交叉・変異
- [ ] genotype → phenotype デコード、成長ステージ
- [ ] 形態が実際に 3D メッシュに反映される（脚長・体色・装飾）
- [ ] 肉食獣追加（FSM）、捕食・戦闘
- [ ] 種 ID と分岐検出、系統樹パネル v1
- **受入基準**: 異なる 2 環境（寒帯/灼熱）で 50 年回すと、平均体色・脚長・毛皮に有意な差が出る

### Phase 3 — 脳と学習（4〜6週）
- [ ] NN 脳（直接符号化 MLP）を Genome に格納、forward 実装
- [ ] 感覚ベクトル 32 次元、出力 14 次元
- [ ] 3-factor Hebb 生涯学習、plasticity/brainSize の遺伝
- [ ] FSM を完全撤去（脳のみで行動）
- [ ] 主観視点パネル（入力バー可視化）
- [ ] CPPN 版との A/B 比較実験
- **受入基準**: 捕食者を導入した環境で 30 世代後に「逃走開始距離」が伸び、学習無効個体群より生存率が高くなる

### Phase 4 — プレイヤーの力（3〜4週）
- [ ] 地形エディタ全ツール、気候スライダー、植生ブラシ
- [ ] クリーチャーエディタ（遺伝子直接編集＋プレビュー）
- [ ] イベント（隕石・寒波・疫病・山火事）
- [ ] 選択圧スライダー、保護区、壁
- [ ] 統計パネル一式（形質推移、ヒートマップ、食物網、絶滅ログ）
- [ ] チャレンジモード 10 本
- **受入基準**: 「地形を作って → 生物を放って → 災害を起こして → 結果をグラフで読む」が一通り気持ちよくできる

### Phase 5 — 磨き込み（継続）
- [ ] セーブ/ロード/エクスポート、自動セーブ
- [ ] タイムラプス録画、高解像度スクショ
- [ ] 進化リプレイ（シード＋コマンドログ）
- [ ] サウンド（環境音、生物の鳴き声が bodySize で変わる）
- [ ] ヘッドレス自動バランス調整の定期実行
- [ ] パフォーマンス最適化（WASM 化の検討）

### Phase 6 — 拡張（お楽しみ）
- [ ] 植物の進化（毒性・棘・成長速度）→ 共進化・軍拡競争
- [ ] 腐肉食・分解者エージェント、水生生物、飛翔生物
- [ ] 文化（模倣学習）と道具使用
- [ ] 遺伝的多様性・染色体数の進化
- [ ] 複数ワールドの接続（移住コリドー）

## 15. リスクと対策

| # | リスク | 影響 | 対策 |
|---|---|---|---|
| R1 | 進化が起きない（全部同じ形になる） | 致命的 | ①変異率を上げる ②近交弱勢で多様性を強制 ③環境を不均一にする（ニッチ分化）④性的選択で中立形質を暴走させる ⑤ストレス時に突然変異率を上げる |
| R2 | すぐ全滅する | 致命的 | ①保護区/初期個体数の下限 ②餓死を緩める ③絶滅危惧時に繁殖ボーナス ④「絶滅レポート」で原因を可視化してプレイヤーに修正させる |
| R3 | NN が意味不明な痙攣行動になる | 大 | ①生得的反射（逃走・摂食）を初期重みに埋め込む ②報酬設計を単純に保つ ③学習率を小さく ④出力に上限クリップ |
| R4 | 数千体でブラウザが死ぬ | 大 | ①SoA＋Worker ②LOD ③感覚・脳の間引き ④上限を設けて自動で sim 周波数を落とす |
| R5 | グラフィックが「気持ち悪い」 | 中 | ①ローポリ＋明快な配色で統一 ②体型パラメータに上限を設けて破綻形態を防ぐ ③アニメーションは gait サイン波で簡潔に |
| R6 | 遺伝子スキーマ変更でセーブが壊れる | 中 | ①スキーマは末尾追加のみ ②`SCHEMA_VERSION` とマイグレーション関数 ③旧版セーブは読み込み時に警告 |
| R7 | 個人開発で完成しない | 大 | ①Phase 単位で「遊べる」状態を維持 ②Phase1+2 だけで成立するゲームにする（進化が見えれば十分楽しい） |
| R8 | ブラウザ差异（Safari の WebGL 制限） | 小 | ①WebGL2 のみに絞る ②Safari で早期にスモークテスト |
| R9 | 観察が単調で飽きる | 中 | ①イベント/チャレンジで外圧を作る ②タイムラプスとログで「物語」を自動生成する |

## 16. 用語集

| 用語 | 意味 |
|---|---|
| ゲノム / Genome | 1個体の全遺伝情報（float 配列） |
| 遺伝子座 / Locus | ゲノム内の1つの形質スロット |
| 表現型 / Phenotype | ゲノムから実際に計算される姿・能力 |
| SoA | Structure of Arrays。同じ項目を連続配列にまとめてキャッシュ効率を上げる手法 |
| LOD | Level of Detail。遠いものを簡略化する |
| Baldwin 効果 | 学習できる個体が有利 → 「学習しやすい遺伝子」が広がる現象 |
| ベルクマン則 | 寒冷地の恒温動物ほど大型になる法則 |
| 近交弱勢 | 近親交配で子の適応度が下がる現象 |
| CPPN | Compositional Pattern Producing Network。座標からパターンを生成する間接符号化 NN |
| 3-factor Hebb | pre×post に加えて報酬（第3因子）で重み更新する学習則 |
