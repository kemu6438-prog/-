## 1. 技術選定（ADR 形式の要約）

| # | 決定 | 理由 | 代替案と却下理由 |
| --- | --- | --- | --- |
| ADR-1 | **TypeScript + Vite + three.js**。`WebGPURenderer`（WebGL 2 自動フォールバック）、シェーダーは **TSL** | WebGPU が主要ブラウザで既定有効になった（2026）。TSL なら両バックエンドで動く | 生 WebGL: 将来性が低い / Babylon・PlayCanvas: 3D Tiles 周りの資産（3DTilesRendererJS）が three 向け |
| ADR-2 | 建物は **`3d-tiles-renderer` で PLATEAU LOD1** を車周辺だけストリーミング | サーバ不要、実績あり（参考実装） | LOD2: 重い / Google 3D Tiles: ポリシー制約（01 章 2.4） |
| ADR-3 | 車は **キネマティック自転車モデル**で動かし、物理エンジンは当面使わない | 自動運転なら十分。決定論的で軽い。浮動原点の付け替えが単純 | Rapier: 手動運転（M5）で導入 |
| ADR-4 | 道路は **OSM をビルド時に静的タイル化**して配信 | 一方通行・信号・車線が揃う。ブラウザから Overpass を叩かない | 地理院ベクトル: 規制属性が無い |
| ADR-5 | **固定タイムステップのシミュレーション** + 補間描画 | 再現性と、描画が遅れても時間が飛ばないこと | 可変 dt: 追従や信号で不安定 |
| ADR-6 | 重い計算は **Web Worker + フレーム予算** | 参考実装で停止の主因だった | メインスレッドで同期処理: カクつく |
| ADR-7 | **サーバレス**（静的ホスティング）。データ前処理はビルド時スクリプト | 運用コストゼロ・公開が簡単 | 自前タイルサーバ: 運用負担 |
| ADR-8 | テスト: **Vitest**（純粋ロジック）+ **ヘッドレス Chrome QA 走行**（画面・性能・規則違反ログ） | 「映像が破綻していないか」は目視頼りになりやすいので機械化する | 手動確認のみ |

## 4. 重要な設計詳細

### 4.1 座標系と浮動原点

- 世界座標は **ECEF**（3D Tiles と一致）。描画用には **ローカル座標**（x=東, y=上, −z=北）に変換。
- `LocalFrame` が現在の原点（緯度・経度・高さ）と変換行列を持つ。車が原点から **1.5 km** 離れたら原点を付け替え。
- 付け替え時に原点依存で持つもの（車・カメラ・AI 車・地形/道路のメッシュ・タイルのルート変換）を **同一フレームで一括変換**。
- 繰り返し模様（窓シェーダー）の周期は 12.8 m の倍数にそろえ、付け替えで模様がずれないようにする。

### 4.2 道路グラフと走行

- ビルド時: OSM → 道路中心線を **交差点で分割**し、ノード/エッジ（車線数・一方通行・速度・信号の有無）に変換 → 約 1 km 四方のタイルにして `.bin`（JSON+圧縮でもよい）で配信。
- 実行時: 車の周辺 3×3 タイルを Worker でグラフ化し、車周辺だけ保持（300 m 動くたびに更新）。
- 経路探索は A*（コスト = 距離/速度 + 右折・信号のペナルティ）。
- 車線中心線: エッジのオフセット曲線。交差点内は **ベジェ曲線**で接続（右左折・直進）。
- 追従制御: **Pure Pursuit**（操舵）+ **IDM**（加減速、前走車・信号の停止線を「止まる障害物」として扱う）。

### 4.3 信号

- OSM の信号点を **25 m 以内の交差点ノードに寄せる**。
- 最も幅の広い道を第 1 現示、45° 以上ずれた流入路を第 2 現示とする簡易サイクル（青 20 s・黄 3 s・全赤 2 s、参考実装の方式）。
- 信号状態は `simTime` の純関数にする（再現性、時間の早送り・巻き戻しに強い）。

### 4.4 ストリーミングと予算管理

- **タイル読み込みはプレイヤー中心の球でマスク**（半径 2.8 km、スマホ 1.6 km）。LRU 上限を設定。
- フレーム処理予算（例: 4 ms）を `FrameBudget` で管理し、重い処理（メッシュ生成・テクスチャアップロード・衝突不要なので物理無し）は **キューに積んで予算内で消化**。
- 起動の段階表示: ① 道路+地面の最小構成で走り出す → ② 近傍建物 → ③ 外壁シェーダー/遠景。

### 4.5 カメラとディレクター

- `CameraRig`: 追従先・オフセット・ばね減衰・FOV を持ち、モード（運転席/チェイス/ドローン）をクロスフェードで切替。
- 壁抜け回避: 追従点からカメラへ **レイキャスト（建物の AABB 空間グリッド）** を撃ち、当たったら手前に寄せる。物理エンジン不要。
- `Director`（P1）: イベント（右左折の接近・信号待ち・橋・長い直線）を検出し、ルールと重みでショットを選ぶ。最短ショット長・連続同じショットの禁止など。

### 4.6 時間・天気・光

- `simTime` から太陽方位/高度を計算し、`Sky`（大気散乱）と `DirectionalLight`、環境マップ（スカイから生成）を更新。
- 夜は窓・街灯・ヘッドライトの発光（ブルーム）。雨は路面の粗さ/反射と雨粒パーティクル。

### 4.7 エラー・フォールバック

| 障害 | 挙動 |
| --- | --- |
| 建物 tileset が取得不可 | 建物なしで走行を継続、HUD 下に「建物データ取得不可」 |
| DEM タイルが取得不可 | 標高 0（平坦）で継続 |
| WebGPU 不可 | WebGL 2 に自動切替。それも不可なら対応ブラウザの案内を表示 |
| Worker 失敗/タイムアウト | メインスレッドの同期フォールバック（参考実装と同様）とログ |

### 4.8 ログと QA

- 構造化ログ（イベント名・simTime・位置）を、画面外の `?qa=1` で取得可能にする。
- **QA 走行**: ヘッドレス Chrome で seed を固定して N 分自動走行し、①スクリーンショット ②FPS・最長フレーム ③違反（逆走・信号無視・建物貫通・スタック）のログを出力。CI の定期ジョブにする。
