> **v0.2 の変更（2026-10-08）**: 手動運転なしに確定／舞台は名古屋を第一候補（東京は予備）／PC 中心でスマホも動かす／想定機材（Intel 内蔵 GPU の PC、Pixel 9a）に合わせて性能目標を 30 FPS に変更。

> ステータス: **ドラフト。** 依頼文から読み取れていない点は「前提」と「未決事項」に分けて明記した。未決事項に答えをもらったら v0.2 に更新する。
> 作業名: **街ドライブビュー**（仮称）

## 1. 概要

車が街中を走る様子を、**ゲームのようにリアルタイムでシミュレーションし、リアルタイムの 3D 映像として眺める**ブラウザアプリ。録画した動画の再生ではなく、毎フレーム街と車と光を計算して描く。

イメージは `kexi/tokyo-od-game`（東京 23 区を PLATEAU の 3D 都市モデルで走る three.js ゲーム）。ただし本作は **「運転する」より「走る映像を見る」** ことを主役にする。

### 1.1 ゴール

1. ページを開くだけで、実在の街（まずは東京）の中を車が自走する映像がすぐ流れる。
2. 時間帯・天気・カメラで「ずっと見ていられる」景観になっている。
3. サーバを持たず、静的ホスティング（GitHub Pages 等）だけで公開できる。

### 1.2 非ゴール（少なくとも初期リリースでは作らない）

- 手動運転（物理ベースの運転ゲーム）。→ 将来の拡張（M5）。
- 違反判定・警察・ミッション・スコア・会話 AI・SNS など参考実装にあるゲーム要素。
- 動画ファイルの書き出し／配信。（※ データ提供元の規約に影響しうるため、やる場合は別途確認）
- 全国対応。まずは東京の限定エリア。

## 2. 前提（確認したい。違えば教えてください）

| # | 前提 | 理由 |
| --- | --- | --- |
| A1 | 主な体験は **「自動運転の運転席（助手席）に座って街を眺める」**。手動運転は作らない（**確定**）。操作は、カメラ・時間帯・天気・行き先の選択程度 | 依頼者の回答 |
| A2 | 街は **実在の名古屋（名駅〜栄周辺）を第一候補**、難しければ東京 | 依頼者の希望。名古屋は PLATEAU の建物データが市内全域にある（詳細な建物は都心部のみ）。実機での確認が M0 で必要 |
| A3 | **PC のブラウザ**が主対象（Intel 第13世代 Core・内蔵 GPU・RAM 32 GB）、**Pixel 9a** でも動かす | 依頼者の環境。内蔵 GPU なので軽さ優先で設計 |

| A5 | 実装は TypeScript + three.js | 参考実装と同系で知見が使える |

## 3. 用語

- **シミュレーション**: 車の位置・信号・時刻を進める計算（固定 60 Hz）。
- **描画**: それを画面に描く処理（モニタのリフレッシュに同期）。
- **浮動原点**: 座標の桁落ちを避けるため、車の近くに座標原点を置き直す手法。
- **LOD1**: PLATEAU の建物モデルで、箱状（壁＋屋根）の簡易形状。

## 5. 非機能要件

| ID | 要件 | 目標値 |
| --- | --- | --- |
| N-1 | フレームレート | 想定機材（内蔵 GPU の PC）の「低〜中」画質で **30 FPS を下回らない**。Pixel 9a の「低」画質で 30 FPS。高性能 PC の「高」画質で 60 FPS（努力目標） |
| N-2 | 動作の滑らかさ | **100 ms を超えるフレームの停止が 10 分連続走行で 0 回**（ストリーミング・Worker 切替含む） |
| N-3 | 初回表示まで | 回線良好時、読み込み開始から車が走り出すまで **10 秒以内**（まず道路と近傍建物のみで開始し、周辺は後から読む） |
| N-4 | メモリ | 建物タイル常駐 200 MB 以内、ブラウザ全体で 1.5 GB 以内 |
| N-5 | 連続稼働 | 1 時間走り続けてメモリが単調増加しない（リーク無し） |
| N-6 | 再現性 | 同じ seed・同じ開始条件で、シミュレーション（経路・交通）が同じになる |
| N-7 | 対応ブラウザ | 最新の Chrome / Edge / Safari 26 / Firefox。WebGPU が無ければ WebGL 2 にフォールバック |
| N-8 | 耐障害性 | データ提供元が応答しない場合、**エラーで止まらず**簡易表示（地面と道路のみ等）で走行を継続し、状況を画面に出す |
| N-9 | サーバ | 自前サーバ無し。静的ファイル + 公共データへの直接アクセス |
| N-10 | ライセンス | 使用データごとに規約を満たす（8 章）。ビルドで第三者ライセンス一覧を生成 |

## 6. 対象エリアとデータ

| 種別 | ソース | 備考 |
| --- | --- | --- |
| 建物 | PLATEAU 3D Tiles LOD1 | 配信は試験運用。タイル URL はカタログ API から引く |
| 標高 | 地理院 DEM5A / DEM10B（PNG）+ EGM2008 | 凸凹はメディアンで均す |
| 地面の色 | 地理院シームレス写真 / PLATEAU オルソ | 標準地図は使わない |
| 道路 | OSM（ビルド時に静的タイル化）。補助に地理院ベクトルタイル | 一方通行・信号・車線・速度が必要なため（未決 Q3） |
| 天気（P2） | 気象庁 | |

初期の対象エリアは **名古屋駅〜栄（広小路通り沿い）** の半径約 3 km（第一候補）。PLATEAU の詳細な建物（LOD2）が都市再生緊急整備地域＝都心部にあり、見栄えの良い区間と重なる。難しい場合は **東京駅周辺（丸の内〜日本橋〜銀座）**（参考実装がスポーン地点にしており、実測値と比較できる）。

## 7. 受入基準（初期リリース = M3 の完了条件）

1. 公開 URL を開くと、ボタン 1 回で東京駅周辺を車が走り出し、**10 分間、操作なしで止まらず走り続ける**（スタック時は自動復帰）。
2. 走行中に **一方通行の逆走・赤信号無視・建物や他車への突き抜けが目視・ログ上 0 件**（QA 走行 10 分 × 3 seed）。
3. カメラ 3 種（運転席・チェイス・ドローン）を切り替えられる。昼・夕・夜が選べる。
4. 想定機材（内蔵 GPU の PC）の「中」画質で平均 30 FPS 以上、100 ms 超のフレームが 0 件。Pixel 9a の「低」画質でも 30 FPS。
5. 出典画面が表示でき、使っているデータのライセンス表記が全て揃っている。
6. データ提供元を意図的にブロックした状態でも、アプリが落ちずに簡易表示で走る。

## 8. 法務・ライセンス上の守るべき事項

| 提供元 | 守ること |
| --- | --- |
| PLATEAU（国交省） | 出典「国土交通省 PLATEAUウェブサイト」を表示し、**加工した旨**を書く |
| 地理院タイル | 利用中は画面に出典表示。標準地図と DEM を重ねた立体地図は作らない |
| OpenStreetMap | ODbL。「© OpenStreetMap contributors」を地図利用箇所に表示。抽出データを配布するなら ODbL で提供 |
| JARTIC（使う場合） | 利用規約の書式で出典と利用日を表示。「JARTIC が作った」ように見せない |
| 地理院ジオイド | モデル値を同梱しない（EGM2008 を使う） |
| Google 3D Tiles（P2 で採用する場合のみ） | 事前取得・キャッシュ・機械解釈の禁止、ロゴと帰属表示、API キー保護 |
| 参考実装（MIT） | コードを流用する場合は著作権表示とライセンス全文を同梱 |

ゲーム内で「**実際の運転・交通規則の参考にはならない**」旨を出典画面に書く。

## 9. リスクと対策

| リスク | 影響 | 対策 |
| --- | --- | --- |
| PLATEAU・地理院ベクトルタイルは試験運用で、予告なく変わる | 街が出なくなる | カタログ API から URL を引く／失敗時フォールバック（N-8）／主要エリアの道路は自前で静的化 |
| LOD1 の建物が灰色の箱で見栄えが弱い | 「見る」ゲームとして魅力が出ない | 外壁シェーダー・夜景・ブルームを早期（M2）から検証。ランドマークだけ自作モデルで補う |
| 道路データの誤り（接続切れ・一方通行の欠落） | 逆走・スタック | OSM を主に、QA 走行（自動で走らせて検出）を CI 化。スタック時の復帰処理（F-2.8） |
| メインスレッドの停止（ストリーミング・メッシュ生成） | カクつき（映像として致命的） | Worker 化 + 1 フレームの処理予算を設けて分割（参考実装の最大の苦労点） |
| 浮動原点付け替えの継ぎ目 | 一瞬の乱れ | 付け替えをカメラ切替のない瞬間／1 フレームで一括、模様の周期を合わせる |
| WebGPU/TSL の API 変更 | ビルド破損 | three のバージョン固定。アップグレードは専用ブランチで |
| モバイルで重い | 動かない | 範囲半径・交通台数・影・シェーダーを画質プリセットで落とす |
